2. TARGET PERSONAS & PRIMARY STAKEHOLDERS
================================================================================
- Persona 1: Autonomous AI Agent Engineers & Swarm Loop Architects
  * Context: Orchestrating fleets of autonomous LLM coding agents, sidecars, and background workers operating across laptops, workstations, and servers.
  * Pain Points: Concurrent file locks corrupt SQLite databases when synced via Dropbox or OneDrive; shared client/server databases require complex networking, credential exposure, and persistent daemons.
  * Value Proposition: Independent local SQLite instances per agent/node; decoupled, asynchronous snapshot-based exchange through a shared transit folder; fail-closed credential filtering ensures no agent leaks prompt tokens, API keys, or secrets into transit.

- Persona 2: Multi-Device & Cloud-Sync Developers
  * Context: Software engineers and power users synchronizing personal knowledge bases, task management apps, and note systems across multiple physical computers via file-sync yards (e.g. sync-master, Syncthing, Nextcloud).
  * Pain Points: Opening live SQLite databases in cloud-synced folders causes `-wal`, `-shm`, and rollback journal corruption, partial writes, and catastrophic database locking.
  * Value Proposition: Clean snapshot atomicity (`sqlite3.backup` + atomic `os.replace`); sidecars are purged before publication; incoming snapshots pass SHA-256 verification and `PRAGMA quick_check` before deterministic row-level merge.

- Persona 3: Local-First & Zero-Egress Tool Builders
  * Context: Developers building desktop, edge, or air-gapped software where user data must remain 100% private, sovereign, and offline-capable.
  * Pain Points: Traditional synchronization solutions (Supabase, Firebase, CouchDB/PouchDB) mandate remote servers, vendor lock-in, recurring cloud costs, and third-party network egress.
  * Value Proposition: Zero network calls, zero external runtime dependencies, 100% standard-library Python core; applications retain full autonomy with custom `MergePolicy` extensibility (tombstones, CRDTs, LWW).

- Persona 4: Enterprise Security, Privacy & Compliance Officers
  * Context: Security leads enforcing strict data handling policies, zero-trust architectures, and secret prevention across corporate development environments.
  * Pain Points: Developers accidentally synchronizing database snapshots containing API keys, private tokens, or customer PII across shared network mounts.
  * Value Proposition: Integrated pre-publication Credential Shield scanning 13+ secret families (`credential-triggers.json`); pluggable HMAC-SHA256 authenticity envelopes preventing untrusted injection; Republica encrypted one-way showcase mode for read-only distribution.

5. GOVERNANCE & RUNTIME INVARIANTS MATRIX
================================================================================
| Invariant ID | Name | Architectural Scope | Guarantee & Verification Mechanism |
|---|---|---|---|
| INV-LOCAL-01 | 100% Local-First & Zero-Egress | System Architecture | Operates exclusively against local SQLite files (`app.db`). Zero telemetry, zero outbound network calls, zero cloud dependencies. |
| INV-SNAP-02 | Offline Snapshot Atomicity | Transit Publication | Live databases are never shared over file transports. Online snapshots captured via `sqlite3.backup` and published via atomic `os.replace`. |
| INV-ROLL-03 | Rollback Journal Clean Isolation | Sidecar Prevention | Backups are closed in rollback-journal mode; all temporary SQLite sidecars (`-wal`, `-shm`, `-journal`) are cleaned fail-closed before manifest creation. |
| INV-PATH-04 | Strict Transit Path Containment | Filesystem Boundary | Manifest and snapshot paths must be direct regular files within canonical transit root. Path traversal (`../`), symlinks, and reparse points fail closed. |
| INV-VERIFY-05 | Two-Stage Integrity & Sanity Verification | Pre-Merge Validation | Every received snapshot must pass SHA-256 cryptographic digest matching and SQLite `PRAGMA quick_check` before inspecting or merging data. |
| INV-SHIELD-06 | Pre-Publication Credential Shielding | Content Inspection | Content is systematically scanned for credential patterns across 13+ secret families (`credential-triggers.json`). Triggers fail-closed push abort naming `table.column`. |
| INV-HMAC-07 | HMAC Authenticity Envelope | Identity & Integrity | Optional pluggable HMAC-SHA256 signature envelope over canonical manifest payload (protocol, namespace, sender ID, filename, SHA-256, size, redaction list). |
| INV-MERGE-08 | Deterministic Row-Level Merge | Data Convergence | Transactional row-level merge (LWW per PK, shared column union for schema drift, explicit tombstone policy). Content hash tie-breaker ensures deterministic convergence. |
| INV-RET-09 | Conservative Retention & Authority Scoping | Garbage Collection | Snapshot cleanup is dry-run by default, scoped strictly to the local node's artifacts. Cross-node deletion (`--all-nodes`) requires explicit administrative opt-in. |
| INV-SLA-10 | Non-Elevation & Multi-OS Parity | Platform Runtime | Runs unprivileged in user mode (RunAsInvoker). Strict operational parity across Linux, Microsoft Windows, and macOS with 48h security SLA. |
